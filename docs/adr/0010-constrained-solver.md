# Our own small SQP solver for Course Corrections and moon returns

A Course Correction (#449) and a `return` from any moon (#450) each find the smallest burn that meets constraints at arrival: a target periapsis and, when given, a target arrival inclination. MechJeb solves both with alglib's `minnlc` in SQP mode. It poses them as multiple shooting over 7 variables (burn time, coast time, and the position and velocity at the sphere-of-influence boundary), with 5 equality constraints that join the legs, 1 inequality, dual-number Jacobians, and Russell's Lambert solver inside the loop. We had no constrained solver. We now pose these problems differently and solve them with a small solver of our own in `Core/Tools/Numerics` (spec #435, decision #447).

- **Single shooting through `Trajectory`.** The variables are the burn's three components, plus the burn time when it is free. One evaluation applies the burn and follows `Trajectory`'s patched conics to the target, then reads periapsis and inclination there. That gives 3 or 4 variables and 1 to 3 constraints, and it reuses the propagation the blocks already trust. One evaluation costs about 0.2 ms.
- **Central finite differences, not dual numbers.** Each Jacobian costs two evaluations per variable. The solver sets the steps in `Scale` units (about 1e-3 m/s for burn components and 1e-2 s for time at Kerbin scale), and callers can't choose them. Smaller steps fall into the periapsis staircase left by the bisected SOI entry time (steps of about 2 to 3 cm). Inclination is clean.
- **Equality constraints and box bounds only.** Only the burn time is bounded, to the window from the earliest to the latest burn. General inequalities wait until a ticket needs one. A Δv limit stays a check after the solve.
- **Inclination is constrained by its cosine,** h_z/|h| − cos(target_inc). Within about 1° of 0° or 180°, where that cosine has zero slope at the answer, the constraint becomes the two equatorial components of the unit orbit normal, which must be zero. Results are checked in degrees.
- **The algorithm is SQP.** The Hessian combines the objective's exact part (|Δv|² is quadratic in the burn) with damped BFGS updates for constraint curvature. Each step solves a dense KKT system, the time bound is held by an active set over bounds, and an L1 merit function drives a backtracking line search.
- **Undefined points shrink the step.** A trial burn with no encounter at the target, or no escape from the moon, makes the evaluation undefined, and the line search backtracks toward the last defined point. A solve must start from a defined point. A Course Correction starts at zero burn on a trajectory that already has the encounter. A moon return starts from an analytic seed, the burn that lines the escape asymptote up for a Hohmann-like descent to target_pe. When that seed is undefined, it falls back to a coarse grid over burn time and prograde Δv.
- **The shape is a static class,** as BrentMin, BrentRoot and Newton are. It takes a problem description and returns a result that carries a status, the constraint residuals and the evaluation count. A non-converged solve returns its best point with that status. The block call turns it into the #439 error lexicon, using a tolerance each caller sets, so failure reaches kOS one way.
- **Budgets:** a Course Correction solves in under 100 ms in its tests. A moon return takes about 100 ms typically and is asserted under 200 ms in the worst case, the grid fallback. Both log their time on the block-call path.

## Considered Options

- **MechJeb's multiple-shooting formulation with dual numbers:** rejected. Core targets .NET Framework 4.8 with no generic math, so duals would need hand-written dual types and dual copies of Conic, Shepperd, Lambert and Trajectory. The bisected SOI entry time would still carry no derivative without implicit differentiation. It remains the route if single shooting fails a long-way return that matters.
- **A trimmed alglib `minnlc`:** rejected. alglib is about 422,000 lines (GPL-2+). Its constrained path pulls in its linear-algebra and QP layers, which are opaque to test and slow to compile. It is the route for a second implementation if our solver fails a scenario that matters.
- **An `IConstrainedSolver` interface with alglib as a fallback:** rejected for now. An interface with one implementation is speculative, and adding one later touches only the solver's two callers.
- **Augmented Lagrangian with an inner Levenberg-Marquardt solve:** rejected. Each multiplier update re-solves the inner problem, which costs several times the evaluations of SQP. SQP converges fast near the answer, and a Course Correction starts there.
- **A nested solve, equality-only over the burn inside BrentMin over time:** rejected. About 25 inner solves cost 100 to 300 ms by measurement.
- **A smooth surrogate (closest approach minus SOI radius) where the encounter is lost:** rejected. It adds a second objective landscape to test, and the seeds keep solves in defined territory.
- **Trying both the short and the long way, or two seeds one moon orbit apart:** rejected. Single shooting has no Lambert step, and the analytic seed picks the escape side that lowers the periapsis.

The cost:
- **About 300 lines of numerics we own,** tested with textbook problems (a constrained quadratic, Rosenbrock with an equality constraint, a scaled two-body problem) and with cases for an active time bound, an equatorial target, backtracking from an undefined region, and a seeded random sweep of perturbed Course Corrections.
- **Finite differences tie accuracy to `Trajectory`'s encounter tolerance.** Tightening its 1e-3 s bisection, or loosening it, moves the safe step size.
- **Hard long-way returns may not converge** from the analytic seed or the grid. If they don't, the multiple-shooting route above becomes a ticket.
