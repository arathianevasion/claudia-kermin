# Script Check and runtime gates instead of a sandbox

kOS has no sandbox: a script can revert or overwrite saves, switch vessels, use physics warp, write or delete anything in the shared `Ships/Script` folder, change global kOS settings and alter other loaded vessels. We guard against Claude's mistakes, not a hostile author, with two layers: a **Script Check** that reads the mod's own compiled opcodes against a forbidden list before Approval, and a few Harmony patches on kOS internals that refuse the most harmful calls (KUNIVERSE save/load/revert/switch, Archive writes, `CONFIG` setters, physics warp, `debugfreezegame`, changes to other vessels) only while a mod-started program runs on that processor. We rejected a check-only approach because runtime-computed names and `run` of written files slip past it, and a full sandbox because kOS offers no hook for one and the threat doesn't warrant it. The cost is coupling to kOS internals, which a kOS upgrade can break; the Core Library and RSVP must pass the same check in CI.
