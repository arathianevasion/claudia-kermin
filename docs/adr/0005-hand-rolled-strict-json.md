# A hand-rolled strict JSON reader and writer instead of SimpleJSON

The spec named compiled-in SimpleJSON (MIT) for the Claude API client. We wrote a small strict reader and writer in `Core/Claude/Json.cs` instead. The client must re-send blocks it does not understand (unknown content block types in an assistant turn, such as thinking or server-tool blocks) byte for byte, and doing that needs each parsed value's raw source span. SimpleJSON builds a tree of values and drops the source text, so re-serializing an unknown block would reorder, reformat or renormalise it (number spellings, escapes, whitespace), and the API can reject or mis-handle a block that doesn't match what it sent. The reader keeps `Raw` on every `JsonNode`, follows RFC 8259 strictly (a malformed Stream event or response is a `JsonException`, not a silently repaired value), and the writer emits the request body. The reader and writer stay in Core, so they run in the same CI tests as the rest of the client and the same code runs in KSP.

We rejected patching SimpleJSON to record spans because the change touches its parser core and we would own a fork of a lenient parser, when the strict reader is a few hundred lines we fully test. We rejected storing each unknown block as a separate substring cut out by offsets outside the parser because the parser already knows the span exactly. The cost is that we maintain our own JSON code; it handles only what the Claude API client needs (no comments, no trailing commas, no streaming parse of a single value), and anything wider should be a new decision.
